# Plan: move LiteRT-LM to v0.19.0 (TODO item 9)

## Context
- **Why now:** v0.19.0 (tagged 2026-10-26, 2,827 commits after v0.18.0) has the two Levenshtein text-merger fixes (`b34761f3`, `b2f2d9d9`) that end Parakeet's dropped text (22.8% of a clean 56 s meeting lost in one session; most of its "noise" errors), and the `rules_cc` fix (`25016d6e`) that made v0.18.1 unbuildable. Its `LITERT_REF` (`dcb657e8`, already in the local `litert` repo, a fast-forward of 647 commits from `26895c9f`) contains LiteRT `dd3db3123`, the WeightLoader ABI fix that CLAUDE.md says unblocks the embedding models' GPU (TODO item 11).
- **What breaks (found read-only, nothing checked out yet):**
  1. **The C API is 1.0.0, a breaking ABI.** Of the 192 `litert_lm_*` functions `Emgu.LiteRT.LM` imports, only the 24 `*_delete` and the 2 error functions are unchanged. Every other one now returns `LiteRtLmStatusCode`, with results in trailing `out_*` parameters; counts and indexes are `size_t`; `set_constraint_provider` takes the enum by value; `token_unions_get_token_at` returns a borrowed pointer (our `Engine.cs:130` deletes it: double free if ported as-is). `litert_lm_get_last_error_code` is gone (unused).
  2. **`omni/asr` is gone.** `AsrEngine`, `AsrEngineConfig`, `model_metadata.json` are deleted (`39306c70`); speech is `omni/speech2text` on `OmniEngine`/`OmniRegistry`; sessions no longer take a client `AudioSource` (our `PushAudioSource` can't be plugged in); `ProcessNext` semantics changed; ASR models load **only from `.litertlm`** - the `.tflite` + `tokenizer.json` Parakeet downloads today fail with "lm_resources must not be null". `litertextern/asrextern` must be rewritten and `ParakeetTdt06BV3` must download `parakeet_tdt_0.6b_v3_5s_i8_stateful.litertlm` (614,588,752 bytes, SHA-256 `66c5a74cf6c2c1d2b990901f6cece5bb53e3214dbceafa0989900a6f0eeb3504`, tokenizer inside).
  3. **CMake TFLite version detection breaks:** at `dcb657e8`, `litert/tflite/CMakeLists.txt` no longer has the `FetchContent_Declare(tensorflow ... GIT_TAG ...)` block that `litertextern/tfliteextern/CMakeLists.txt:74` greps (Catalyst and Windows CMake builds).
  4. **Versions move:** LiteRT `LITERT_EXPERIMENTAL_VERSION` 2.3.0 → 2.4.0 (every `Emgu.LiteRT.*` package), LiteRT-LM 0.18.0 → 0.19.0, C API 0.2.0 → 1.0.0 (all derived by CMake from `version.bzl`; nothing hard-coded except the Windows GPU scripts).
  5. `liblitert-lm` now exports only `litert_lm_*` (macOS/iOS `-exported_symbol` + `-dead_strip`; Linux/Android a version script). `libomniextern` doesn't link `liblitert-lm` (it compiles the omni code into itself, 20 MB), so this doesn't affect it; it does shrink `liblitert-lm`.
- **Outcome:** the natives and packages on v0.19.0 / LiteRT 2.4.0 for macOS, Mac Catalyst, iOS and Android; the C# layer on C API 1.0.0; Parakeet on the `.litertlm` with the fixed merger, re-scored; the embedding GPU check done (or explicitly deferred). Windows is listed for the user's Windows machine; CI (`native.yml`) builds it on push.

## Phase 2b: exceptions the Emgu CV way
Emgu CV (`/Volumes/bb/github/emgucv`) never throws from a native callback, because a managed exception unwinding through native frames is fatal on .NET (`Emgu.CV/Core/CoreInvoke.cs:64-78`). Instead:
- **Native:** every extern function catches its C++ exception (`CVAPI_CATCH_CV_ERRORS` in `Emgu.CV.Extern/emgu_error.h`) and records it in a thread-local pending error (`emguRecordError`), read back by `cveHasPendingError`/`cveCheckPendingError`.
- **Managed:** the callback (`CvErrorHandler`) only saves the error in `[ThreadStatic]` fields and returns. Each wrapper calls `CvInvoke.CheckError()` right after the P/Invoke, which throws `CvException(status, funcName, errMsg, fileName, line)`, falling back to the native pending error where no callback is registered (iOS, `EMGU_CV_DISABLE_ERROR_HANDLER=1`).
- **Tests:** `AutoTestVarious.TestException` asserts the status (-215) of a caught `CvException`.

How each Emgu LiteRT layer compares, and the change:
1. **`Emgu.LiteRT.LM` - adopt it fully, as part of the 1.0.0 port.** v0.19.0 already gives the native half: every call returns a `LiteRtLmStatusCode` and records a thread-local message (`litert_lm_get_last_error_message`). Make `LiteRtLmException` carry `Status` (`LiteRtLmStatusCode`), `FunctionName` and `ErrorMessage` (message format "LiteRT-LM: {function} failed ({status}): {message}", like `CvException`'s "OpenCV: ..."), keeping the `(string)` constructor for the speech layer. One `LiteRtLmInvoke.CheckError(LiteRtLmStatusCode status, string functionName)` replaces `CheckPtr`/`CheckStatus(int)` (`LiteRtLmInvoke.cs:94-111`) and runs right after each import, on the same thread. Also map `Cancelled` to `OperationCanceledException` (cancel_process paths) if the existing code relies on that - check `Chat`/`LiteRtLmChatClient`'s cancellation handling.
2. **`Emgu.TF.Lite` - fix the unsafe callback (the same bug Emgu CV fixed).** `TfLiteErrorHandler` (`TFLiteInvoke.cs:20-26`) throws a plain `Exception` from inside `tfeReportError`, which TFLite calls in the middle of native work (`tfliteextern.cc:17-21`, the model and interpreter error reporters at :46/:136); the comment at `tfliteextern.cc:243` already notes .NET can't unwind that on macOS/Linux, and it's skipped on iOS, so there errors are silent.
   - Native: `tfeReportError` also records the message in a thread-local pending error; add `tfeHasPendingError`/`tfeGetPendingError(char* buffer, int size)` (clears it). Keep `tfeRedirectError` for compatibility.
   - Managed: the default handler only stores the message (`[ThreadStatic]`) and returns; new `TfLiteException(Status, string message)`; `TfLiteInvoke.CheckError()` after the calls that can fail. The public API returns `Status` from `AllocateTensors`/`Invoke`/`ResizeInputTensor`/`ModifyGraphWithDelegate` (`Interpreter.cs:62-236`): keep the return value (no behaviour change for callers who check it) and make the message available as `TfLiteInvoke.LastErrorMessage`; throw `TfLiteException` only where a failure returns null today (model loading, interpreter creation) - those currently throw from the callback or NullReference later.
   - Needs a `tfliteextern` rebuild: it rides on Phase 1's builds (add before the macOS build).
3. **`Emgu.LiteRT`** - already status based (`LiteRtInvoke.CheckStatus` → `LiteRtException(Status)`, `LiteRtInvoke.cs:58-62`), no callback; LiteRT's C API has no last-error message. Add `FunctionName` to `LiteRtException` for parity only if cheap (pass it at the call sites); otherwise leave.
4. **omniextern** - its functions already catch and return errors through `char** error` (no throwing through frames). After the port, switch to the same shape as LiteRT-LM: return a status code and keep a thread-local last error (`omniextern_get_last_error_message`), so `AsrInvoke` reuses `CheckError` and throws `LiteRtLmException` with a status.
- **Tests (model-free where possible):** an invalid `.litertlm` path → `LiteRtLmException` with `Status == NotFound` (or what 1.0.0 returns) and a message, on every platform; a corrupt `.tflite` → `TfLiteException`, the process survives (today it can crash on macOS); a bad input index → `Status.Error` returned plus `LastErrorMessage` set. These need the natives, so `Native` category.
- **Docs:** CLAUDE.md "Key Conventions → Error handling" (currently "redirected via a callback ... thrown as managed exceptions": rewrite to the record-then-check rule), `docs/litert-lm.md` C API facts.
