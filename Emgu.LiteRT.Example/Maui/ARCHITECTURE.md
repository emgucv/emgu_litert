# MAUI demo architecture

How the MAUI demo's code is organised. Moved here from CLAUDE.md, which keeps the short version.

## Folders, the chat page and its features

- The demo's sources are in folders by area - `Chat/` (the chat page `LiteRtLmChatPage.cs`, a `ChatPage` of `Emgu.LiteRT.LM.Maui` - see the next section; `IDemoHost`, the templates, `UserMessageInfo` and `StreamingBubble` - the page's data for a message and a reply, in their `Tag` -, `DemoAttachmentSource`, `AlertAudioReplySpeaker`, `SearchEmbedder`), `Chat/Features/` (the demo's `ChatFeature`s, all on `DemoFeature` - `CameraFeature` and the others listed below; add a member to `IDemoHost` only when one of them needs it); document, photo and past-chat search share the search model through the library's `SearchEmbedder` (`Emgu.LiteRT.LM.Maui`: loading, the GPU-to-CPU fallback, `Gate` - one embedding at a time - and releasing it; `ModelSettingsFeature` owns it, and the page hands it to the library's `PastChatsFeature` in a `SearchServices` with the demo's `WorkloadService`), which reads Settings > Embedding model through `ISearchModelChoice` (`ModelSettingsFeature`), `Vision/` (the image demo pages and `DetectorFactory`, whose GPU-check pictures the chat's camera uses too; the live camera is `Emgu.LiteRT.Models.CV.Maui`'s `LiveCamera`), `Audio/`, `Services/` (device actions, the settings adapter, ML Kit; the photo library, reading documents and downloads are the library's), `Pages/` (About, Licences, Storage, Model Checker) - all in namespace `Maui.Demo.Lite`.
- Code that needs no UI or device - saved chats (`ChatStore`), `ChatToolGroups`, `ChatPlannerInstructions`, `ChatSessionTools`, chat export and search, storage bookkeeping - is in the class library `Emgu.LiteRT.Example/Maui.Demo.Lite.Core` (net<major>.0 from `cmake/Maui.Demo.Lite.Core.Directory.Build.props.in`, `InternalsVisibleTo` the demo and the test project), which both reference instead of the tests linking demo files; it must not use MAUI.
- Add new testable logic there.

## The reusable chat page, and where the demo is going

- Since 2026-10-26 `Emgu.LiteRT.LM.Maui` has `ChatPage`: the whole chat page an app drops in (header, `ChatView`, chips, model and chat lists, settings sheet or side panel, private mode) with an agent whose tools come from `ChatFeature`s (`Emgu.LiteRT.LM.Agents`' `ChatSkill` plus a settings section, a chip and cards), composed per message by a `ChatSkillSet`. The built-in features are the demo's core tools, memories, web, location, clipboard and goals; see `docs/agents.md`.
- Since the swap of 2026-10-26 (phase B) the demo's `LiteRtLmChatPage` *is* a `ChatPage` (`Chat/LiteRtLmChatPage.cs`, one file): its `CreateOptions` gives the library the catalog's models as `ChatModelOption`s (`ChatModelOptions.FromCatalog`, with the server as the remote option), `ChatStore` as the `IChatHistoryStore` with `AutoSave` off (the page saves each exchange itself, with the message's language and its own step lines; the pictures the reply drew and the documents it wrote are the reply's `SavedFiles`, saved and restored the library's way since phase C), `ChatSettingsAdapter` (the demo's keys), `ShowBackButton`, `ShowCpuThreads`, `ConfigureEngine` (the benchmark and the audio threads), the camera feature's `AlertAudioReplySpeaker`, the Export action, and the features in the settings' order: the library's `VoiceLanguageFeature` (since phase C), the library's core tools, memories, web, location and clipboard, then the library's `CameraFeature` and `ExerciseFeature` (`Emgu.LiteRT.LM.Maui.CV`, since phase C; the page gives them a `VisualDetectors` over `DetectorFactory` and a Save As dialog for snapshots), the library's `ServerFeature` (`Emgu.LiteRT.LM.Maui.OpenAI`, since phase C; it is the remote option's `IRemoteChatModel`, so the page overrides nothing for the server), the library's `McpFeature` (`Emgu.LiteRT.LM.Maui.Mcp`), `ModelSettingsFeature`, the library's `ImageFeature` (`Emgu.LiteRT.LM.Maui.Images`, since 2026-10-27; the page gives it the workload, its model selector and a Save As dialog), the library's `StorageFeature` (since phase C; the page gives it a `StorageCatalog` over `ChatStore` with the catalog's models, the two search models and the image model's folder, and the `SearchServices`; the features with a stake in what it deletes are `IStorageParticipant`s - the library's searches and documents, the demo's `ImageFeature`), the library's `ExportFeature` (since phase C; the page gives it `ChatExporter.ExportAsync` over `ChatStore`), `DocumentsFeature`, the library's `VoiceModeFeature` (since phase C), the library's `TaskFeature` (since phase C; its task-mode client comes through `CreateMessageClient`), `TranscriptFeature`, `TranslationFeature`, the library's `DeviceActionsFeature` (since phase C, with `DeviceActions` - the platform code - beside it in the library), the library's `WrittenDocumentsFeature` and `MeetingFeature` (the demo gives the meetings its camera feature's foreground service and its document attaching), the library's `GoalsFeature` (over `ChatStore.Goals`; since phase C), `PastChatsFeature` (over `ChatStore` as its `IChatSearchStore` and the `SearchServices`; phase C too) and `DocumentsFeature` (`Emgu.LiteRT.LM.Maui.Documents`, over `ChatStore` as its `IChatDocumentStore`; the page's `SendCoreAsync` calls `PrepareRequestAsync` for its excerpts), the library's `PhotoSearchFeature` (over `ChatStore` as its `IPhotoIndexStore`; the page's workload is the library's `DeviceIndexingWorkload`). The page overrides `SendCoreAsync` (the document's excerpts as the message's context, task mode's client, the resend after a refused request - the base's `ShouldResend`, the rerun after a stub, the translation offer, the memories used, saving), `OnBeforeStreamingAsync` (the excerpts searched again after compacting), `ConfigureConversation` (the groups' overhead), `CreateChatClient` (the watchdog on the device model's context management), `OpenChatAsync` (the records' extras and cards), `StartNewChat`, `OnPrivateModeChangingAsync`, `OnNavigatedFrom` (everything let go of), and implements `IDemoHost` for its features and the "+" menu (`DemoAttachmentSource` over `MenuSheet`, a layer while open). The message and reply templates stay the demo's (`ChatTemplates.xaml`: `UserMessageInfo` and `StreamingBubble` in the items' `Tag`); the app pins the light theme (`App.xaml.cs`), as the demo's pages are drawn in fixed light colours. Phase C (2026-10-26/27) moved the features any app would want into the library one at a time - the packages `Emgu.LiteRT.LM.Maui.Documents`, `.Mcp`, `.OpenAI`, `.CV` and (on 2026-10-27, as a follow-up) `.Images` came out of it - and left the demo its own three: `ModelSettingsFeature` (its embedding-model choice), `TranslationFeature` and `TranscriptFeature` (its templates and saving). `TODO.md` item 55; the plan in `history/CHAT_PAGE_PLAN.md`.
- Phase B's wrappers (2026-10-26): `Chat/Features/DemoFeature.cs` is the base of the demo's own `ChatFeature`s - the library's host plus the demo's `IDemoHost` (`Chat/IDemoHost.cs`: the store, the workload policy, whether the page is shown; reloads, the model list, the model's release, the recording state, voice sends and stopping the reply moved to `IChatPageHost` in phase C), the message being sent (`Context`), whether the page is shown, and the window coming to the front or leaving it; each registers itself in `IChatPageHost.Services`, so the others find it (`Host.Services.Get<CameraFeature>()`). `CameraFeature` (ten partials: the preview panel, the camera monitors with their snapshots, clips and photos, the sound monitors, the alert sounds, the camera click, the monitors' info, the background service; its panels are `IChatOverlays` overlays, its visual agent registry and `AlertAudioReplySpeaker` are services), `DocumentsFeature` (the chip is its `BuildComposerView`, the excerpts come from `GetDocumentContextAsync`), `McpFeature`, `VoiceModeFeature` (a layer, `SetHandsFree`; the library's since phase C), `ServerFeature` (the remote option's `ConnectAsync`, `CreateChatClient`, `AskOnceAsync`; the library's since phase C), `TranscriptFeature` (`Track`), `ExportFeature` (a `ChatAction`; the library's since phase C), `StorageFeature` (the library's since phase C), `ModelSettingsFeature` (owns the `SearchEmbedder`; the `SearchServices.Choice`); `Services/WorkloadService.cs` the workload policy and the index-embedding gate.
- Phase B2.5 (2026-10-26): the ten feature classes that predated the library became `DemoFeature`s too, each with its tool group (`ToolGroups()`), settings section, chip or cards, and the page's hooks instead of the page's calls - `TranslationFeature` (the translate row and the thinking-language check, `OnReplyCompleted`), `DeviceActionsFeature` (the group with `rerunAfterStub`, the outcomes in `OnToolStepCompleted`; the library's since phase C), `WrittenDocumentsFeature` (its group carries `MeetingFeature`'s tools), `GoalsFeature` (its group carries `ExerciseFeature`'s tools; loads in `PrepareAsync`), `PastChatsFeature` and `PhotoSearchFeature` (indexing from `OnAppearing`/`OnAppResumed`, the switches from `OnPrivateModeChanged`), `MeetingFeature`, `ExerciseFeature` (the camera through `Host.Services.Get<CameraFeature>()`), `TaskFeature` (the Plan chip, `TakePlan`, the task-mode client; the library's since phase C), `ImageFeature` (the image model in `OnAttached`, its section after the model selector; the library's since 2026-10-27). The old `IChatHost`, `DemoChatHost`, `DemoToolsFeature`, `DemoSectionsFeature` and `TaskChipFeature` are gone; the page's `Parts` holds every feature, and `IDemoHost` lists no features - they find each other through `Services`.

## Adding to the chat page

- A feature: a class in `Chat/Features/` on `DemoFeature` (or the library's `ChatFeature`, when it needs nothing of the demo), with a unique `Name`, registered in `RegisterServices` if other features reach it, created in `LiteRtLmChatPage.Build()` as a field of `Parts` and added to the features list where its settings section belongs. Its tools are `Tools(context)` (every message) or `ToolGroups()` (a group the router turns on when the message mentions it, with a stub otherwise - `ChatToolGroups` holds the names, summaries and keywords, tested without UI); its instructions `InstructionsAsync`; the settings section `BuildSettingsSection`, a chip `BuildComposerChip`, a view above the message box `BuildComposerView`, cards `Host.AddCardToReply`/`AddNotice`, panels `Host.Overlays`; and the page's events `OnAttached`, `OnAppearing`, `OnModelChanged`, `OnReplyCompleted`, `OnChatOpened`, `OnToolStepCompleted`, `OnNewConversation`, `OnPrivateModeChanged`, `OnAppResumed`/`OnAppStopped`. It talks to the page through `Host` (`IChatPageHost`) and `Demo` (`IDemoHost`) - add a member to `IDemoHost`, implemented by the page, only when a feature needs something the two don't have - and to the others through `Host.Services.Get<T>()`. Describe it in `FEATURES.md`.
- A page-wide behaviour (something on every send, in the model's setup, when a chat opens): an override in `LiteRtLmChatPage.cs` of the `ChatPage` virtual listed above, calling the base.
- A library change (a part every app wants) goes into `Emgu.LiteRT.LM.Maui` or `Emgu.LiteRT.LM.Chat` instead, with the `MauiChat` sample checked; `docs/agents.md` records them.

## The home page

- The MAUI demo's home page (`MainPage.xaml.cs`) has two tabs, pills like the Emgu CV demo's category pills: "LiteRT-LM" (the chat; on the platforms with LiteRT-LM) and "TF Lite" (Coco SSD MobileNet, MobileNet, Inception, Model Checker); the last one used is kept in Preferences (`main_page_tab`).

## Settings

- The chat page's settings are `ChatSettings` (`Maui.Demo.Lite.Core/Chat/ChatSettings.cs`): typed properties with their Preferences keys and defaults in one place, never throwing (a failing store gives the default). The app's instance is `AppSettings.Chat` (`Services/AppSettings.cs`, over MAUI's Preferences); tests use `InMemorySettingsStore` (`UnitTestChatSettings`). Add a new setting there rather than calling `Preferences` directly.

## The model list

- The chat page's models are `ChatModelCatalog` (`Maui.Demo.Lite.Core/Chat/ChatModelCatalog.cs`): `ModelChoice`, `ModelOption` (name, file, size, what each model can do, its GPUs and context window), the list per `ChatPlatform` (Gemma 4 12B on Mac Catalyst and Windows only) and `Create(choice)`. The page takes its own platform's list; `UnitTestChatModelCatalog` checks it. Add a model there.
