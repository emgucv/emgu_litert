# Emgu LiteRT MAUI demo

A .NET MAUI app showing the Emgu LiteRT APIs: image classification and object detection with the TensorFlow Lite
Interpreter API (`Emgu.TF.Lite`), LiteRT's CompiledModel API (`Emgu.LiteRT`), and an on-device chat with LiteRT-LM
language models (Qwen3, Qwen3.5, Gemma 4 - with images, voice messages and an agent that can search Wikipedia / the
web). It runs on Windows, Mac Catalyst, iOS and Android.

The demo builds against the projects in this repository, not NuGet packages, so the native libraries must be built
first. The commands below are run from the repository root and assume .NET 10 (the app targets the .NET version CMake
found - use your version's number otherwise).

## 1. One-time setup

- .NET SDK with the MAUI workloads: `dotnet workload restore Emgu.LiteRT.Example/Maui.Lite/Maui.Demo.Lite.csproj`
- For the native builds: Bazel (the version in `LiteRT-LM/.bazelversion`; Bazelisk picks it automatically) and
  CMake 3.16 or later; Xcode for Mac Catalyst and iOS; the Android SDK, NDK and a JDK for Android.
- The LiteRT-LM submodule's prebuilt libraries are stored with Git LFS: `git -C LiteRT-LM lfs pull`.

## 2. Build the native libraries for the platform

| Platform | Commands | Output |
|---|---|---|
| Mac Catalyst | `platforms/ios/cmake_build_tflite_catalyst arm64` (and `x86_64` for Intel / universal builds), plus `platforms/macos/bazel_build_tflite_macos_fat` for LiteRT-LM | `lib/ios/libtfliteextern_darwin_<arch>.a`, `lib/runtimes/osx/native/*.dylib` |
| iOS | `cd platforms/ios && ./bazel_build_xcframework && ./bazel_build_litert_lm_ios` | `lib/ios/libtfliteextern_ios.xcframework`, `CLiteRTLM.xcframework`, `GemmaModelConstraintProvider.xcframework` |
| Android | `platforms/android/bazel_build_tflite_android arm64` (also `x86_64`, `arm`, `x86` as needed); on macOS set `ANDROID_HOME` first, e.g. `export ANDROID_HOME=~/Library/Android/sdk` | `lib/android/<abi>/*.so` |
| Windows | `platforms\windows\bazel_build_litert.ps1 64` | `lib/runtimes/win-x64/native/` |

Notes:

- LiteRT-LM (the chat page) is only built for Apple Silicon on macOS / Mac Catalyst, and for `arm64-v8a` and
  `x86_64` on Android; on other architectures the rest of the demo still works.
- On iOS, LiteRT-LM needs iOS 26.4 or later at run time.

## 3. Generate the project settings

The projects' target frameworks and package versions are generated by CMake into `Directory.Build.props` files:

- macOS: `platforms/macos/build_emgutf` (or `cmake .` in an existing `build/` folder)
- Windows: `platforms\windows\build_emgu_litert.ps1`

Run it again after pulling changes that add a project (otherwise the build fails with NU1201, "does not support any
target frameworks") or after switching .NET SDKs.

## 4. Build and run

### Mac Catalyst

```bash
dotnet build Emgu.LiteRT.Example/Maui.Lite/Maui.Demo.Lite.csproj -f net10.0-maccatalyst -c Debug -p:ValidateXcodeVersion=false
open "Emgu.LiteRT.Example/Maui.Lite/bin/Debug/net10.0-maccatalyst/maccatalyst-arm64/Emgu LiteRT.app"
```

`-p:ValidateXcodeVersion=false` is needed when the .NET Mac Catalyst SDK pack doesn't match the installed Xcode
exactly (e.g. pack 26.5 with Xcode 27). Add `-t:Run` to build and launch in one step. Opening the `.app` (rather than
running its executable from a terminal) makes macOS ask for microphone access for the demo itself.

### iOS simulator

```bash
dotnet build Emgu.LiteRT.Example/Maui.Lite/Maui.Demo.Lite.csproj -f net10.0-ios -c Debug -p:ValidateXcodeVersion=false -p:RuntimeIdentifier=iossimulator-arm64
xcrun simctl install booted Emgu.LiteRT.Example/Maui.Lite/bin/Debug/net10.0-ios/iossimulator-arm64/Maui.Demo.Lite.app
xcrun simctl launch booted com.emgu.litert
```

Boot a simulator first (Simulator app, or `xcrun simctl boot "<device name>"`); the LiteRT-LM chat needs an iOS 26.4
or later runtime.

### iOS device

Device builds need code signing (an Apple developer team and provisioning profile). With those set up:

```bash
xcrun xctrace list devices                     # find the device's UDID
dotnet build Emgu.LiteRT.Example/Maui.Lite/Maui.Demo.Lite.csproj -t:Run -f net10.0-ios -c Release -r ios-arm64 -p:_DeviceName=<UDID>
```

(Not yet verified with this version of the demo.)

### Android

Start an emulator or connect a device, then:

```bash
dotnet build Emgu.LiteRT.Example/Maui.Lite/Maui.Demo.Lite.csproj -f net10.0-android -c Debug -p:RuntimeIdentifier=android-arm64 -t:Run
```

- `-p:RuntimeIdentifier=android-arm64` builds only the ABI you need (use `android-x64` for an x86_64 emulator).
- With more than one device connected (`adb devices`), pick one with `-p:AdbTarget="-s <serial>"`; `-t:Install`
  installs without launching.
- If the app doesn't start after installing, launch it with
  `adb shell am start -n com.emgu.litert/crc64f6b2cafaa50b22b8.MainActivity`.
- A headless emulator: `$ANDROID_HOME/emulator/emulator -avd <name> -no-window -no-audio`; wait for
  `adb shell getprop sys.boot_completed` to print `1`.

**Reusing the Mac's models**: `tools/deploy_android [serial ...]` (all connected devices if none are given) builds,
installs and starts the Debug app on each device, then copies the LiteRT-LM models this Mac already has - downloaded by
the Mac Catalyst demo (`~/Documents/LiteRT-LM`) or the tests (`~/Library/Application Support/LiteRT-LM`) - into the
app's model folder, so the phone doesn't download them again. Only the models the Android app offers are copied (not
Gemma 4 12B), only if missing (by size) and if the phone keeps 512 MB free; each is streamed through `adb exec-in run-as`
(the app's folder is private, so it needs the debuggable Debug build), and the file's time and `.sha256ok` marker go
with it, so the app doesn't hash it again either. Gemma 4 E2B (2.6 GB) takes a few minutes over Wi-Fi. `NO_BUILD=1`
only copies the models.

**A phone over Wi-Fi** (Android 11+): on the phone, open Settings → Developer options → Wireless debugging, then
"Pair device with pairing code". On the computer:

```bash
adb mdns services                              # lists the phone's pairing and connect ports
adb pair <ip>:<pairing port> <code>            # once per computer
adb connect <ip>:<connect port>
```

The connect port changes whenever Wireless debugging is switched off and on. The phone's address on a VPN such as
Tailscale works for `adb connect` too, so the phone can be reached away from the local network. Screenshots:
`adb exec-out screencap -p > screen.png` (on a foldable, add `-d <display id>` from
`adb shell dumpsys SurfaceFlinger --display-id`).

### Windows

Open the project in Visual Studio, or after the native build and `build_emgu_litert.ps1`:

```powershell
platforms\windows\build_emgu_litert.ps1 "" nuget
dotnet build Emgu.LiteRT.Example\Maui.Lite\Maui.Demo.Lite.csproj -f net10.0-windows10.0.22621.0 -t:Run
```

For GPU chat on Windows, first build the matching runtime bundle with
`platforms/windows/bazel_build_windows_gpu.ps1`. The demo includes that bundle
automatically. The chat model picker has **CPU models** and **GPU models** sections;
select a GPU entry to use GPU inference. Tap either section heading to expand or collapse its models; the selected
model's section opens by default, and expansion choices are kept while the page is open. Switching backend reloads
the model while retaining the conversation.
Qwen3.5 loading can take several minutes. See [Windows GPU build instructions](../../platforms/windows/README.windows-gpu.md)
for output locations, alternate bundle directories, and CPU-only builds.

Model downloads retain their progress when cancelled or interrupted. The picker and download card show
**Download paused** and **Continue**; resuming uses the server's strong ETag so different file revisions are never
appended together. Servers without a strong validator restart safely. Completed downloads are checked against
SHA-256 before becoming model files. Rows also show downloaded state and size on disk.

## The home page

Like the Emgu CV demo, the home page has two tabs: **LiteRT-LM**, with the chat, and **TF Lite**, with the TensorFlow
Lite (Interpreter API) demos - object detection, image recognition and the model checker. The tab used last opens
again.

## Using the chat page

- Choosing a model you haven't downloaded yet shows its download size (Qwen3 0.6B ~350 MB, Qwen3.5 0.8B ~1.3 GB,
  Gemma 4 E2B ~2.6 GB, E4B ~3.7 GB, Qwen3.5 4B ~2.8 GB) with a Download button; models already on the device start
  loading as soon as they are selected, and the page reopens with the model used last. The first load after a
  download checks the file once (a few seconds for the larger models); you can type meanwhile, and a message sent
  while the model loads is sent when it's ready.
- Replies are formatted (headings, bold, italic, lists, links), code is shown in a code block with a Copy button, and
  maths written in LaTeX ($x^2$, $$\frac{a}{b}$$) is shown as text - x², a/b, √2, ≤ - with formulas on lines of their
  own centered.
- Chats are saved on the device after each reply; the history button (or the Chats list in the side panel on wide
  screens) reopens or deletes one.
- **Chat settings → Private chat** starts a fresh session marked **Private · Not saved** in the header. Messages,
  pictures, recordings, document indexes and summaries are not saved. Memories and past-chat search are unavailable.
  Starting another chat, ending private mode or closing the chat page discards its session content; opening saved
  history asks to end the private session first. Private mode resets when the app restarts. Web search still follows
  its own toggle and may send requests online, and images you explicitly save stay saved. Downloaded models and
  prepared weight caches are kept; private document embeddings stay in memory.
- **Chat settings → Storage** lists model files (including partial downloads and CPU/GPU caches), Z-Image data,
  saved documents, photo/past-chat search indexes, chat attachments and shared export copies, with sizes, a managed
  storage total and free space. Delete asks for confirmation and releases loaded models before removing their files.
  Database entries show stored-data estimates; the database's disk size is counted once in the total. Deleting an
  index keeps chats/photos; deleting attachments keeps chat text; deleting a document detaches it from saved chats
  but keeps excerpts already used in answers. SQLite is compacted after these deletions. Removing the selected
  search model turns document/photo/chat search off until you explicitly download it again from Storage; search
  switches can then be enabled again. The image-model settings link opens the same Storage page.
- Use the chat header's export button, or **Export** beside a saved chat, to open the system share sheet with a ZIP
  containing `chat.md` and its saved pictures and recordings. Extract the ZIP and open the Markdown file to follow
  its relative attachment links. The export includes thinking, tool steps and document excerpts; missing files are
  noted. An attached document exports its saved text and images, since the app does not retain the original PDF.
  Only the selected chat is exported; global memories, credentials and search indexes are excluded. Exports stay in
  the app cache for recipients to read and are cleaned up on a later export after a day. Import is not yet supported.
- Enable "Search past chats" in chat settings to let Gemma 4 use `search_chats` for previous discussions and decisions.
  Saved user and assistant text is indexed locally in the background using the selected embedding model. Searches
  support dates such as "last week", return excerpts with titles and dates, and show buttons above the reply to open
  matching chats after the reply finishes. The current chat is excluded. Initial results can be incomplete while
  indexing runs. Changing embedding models rebuilds the index; deleting a chat removes its entries. The setting is
  off by default and is saved across restarts. Turning it off deletes the index and keeps the saved conversations.
  This works independently of Web search and Memories; attachments, reasoning, and tool steps are not indexed.
- The models can take in about 4,096 tokens of conversation (a few pages of text; a photo is ~270, voice ~25 per
  second) - Gemma 4 8,192 on Mac and Windows. Opening a long saved chat takes a while, since the model reads it again
  (measurements in [Performance.md](Performance.md)).
- Gemma 4 12B (~6.9 GB download) is available on Windows and Mac Catalyst for code and harder questions.
  Windows currently offers it under CPU Models: CPU text/image/audio input passed, but GPU image inference on
  an RTX 3070 returned corrupted special tokens despite working text chat. It needs substantial system memory;
  CPU inference can be slow. On a Mac, the Gemma 4 models run on the GPU through the optional `Emgu.LiteRT.Metal.runtime.maui.macos` package
  (select an entry under "GPU models"); the first load of a model there builds a cache next to it (~6 GB for 12B).
- On Android, Gemma 4 E2B can be selected under "GPU models" (CPU fallback is offered if GPU initialization fails),
  through the optional `Emgu.LiteRT.OpenCL.runtime.maui.android` package the demo references:
  replies take about a second instead of ~6, and reopening a long chat ~8 s instead of ~2 minutes. The first load on
  the GPU takes about 30 s and keeps a ~0.8 GB cache next to the model. When a chat gets longer, Gemma 4 and Qwen3.5 4B summarize the earlier messages and continue from the summary
  (this takes a few seconds); the small models drop the earliest messages instead. A line in the conversation shows
  where the model's memory starts - tap it to read the summary - and Settings shows how full it is, with "Compact now".
- Gemma 4 has tools: a calculator for exact arithmetic; memories - tell it something about yourself ("I'm
  vegetarian") and it remembers it in later chats (Settings → "Memories about you" lists them, each with a delete
  button; they stay on the device); and with Web search on, the weather (Open-Meteo), Wikipedia and - with a Tavily
  key - the web.
- With "Share my location" on (Settings, off by default), Gemma 4 can look up your town and approximate position,
  e.g. for "what's the weather here?" (with Web search on). The device asks for location permission the first time;
  the place name comes from Apple's or Google's map service.
- "Think" and "Web search" (Gemma 4) are per-message switches above the message box. Both keep their last setting
  across app restarts; Web search defaults to off. "Think" is on by default and
  keeps the last setting: the model reasons before answering, which gives better answers but takes longer and uses
  more of its context (so long chats are compacted sooner). While the model thinks, the reply shows "Thinking..."
  and the last few lines of it; once the answer starts, the thinking collapses to "Thought for N s" - tap it to read
  it all, formatted like the answer (code blocks, maths). General web search (including news) requires a Tavily API
  key in Settings > Web search. Without a key, Wikipedia, reading supplied links, weather and currency conversion
  remain available. A notice above the message box explains the missing key when Web search is enabled; the agent
  also receives this limitation so it can explain how to enable general search. Your searches leave the device.
  In Settings, select **Save API key** (leaving the key field also saves). The app verifies the value in secure
  storage before reporting success. If saving fails, it shows a persistent session-only warning and allows retrying
  the same key. Clear the field and save to remove a stored key; the app reports removal failures too.

  **Mac Catalyst key persistence:** MAUI SecureStorage uses the data-protection Keychain, which requires a signed
  app and a matching Mac Catalyst provisioning profile. Ad-hoc builds remain usable with session-only keys.
  Obtain a Mac Catalyst development profile for `com.emgu.litert` using your Apple developer team, then build with:

  ```bash
  dotnet build Emgu.LiteRT.Example/Maui.Lite/Maui.Demo.Lite.csproj -f net10.0-maccatalyst -c Debug -p:ValidateXcodeVersion=false -p:CodesignKey="Apple Development: Your Name (CERTIFICATE_ID)" -p:CodesignProvision="PROFILE_UUID"
  ```

  The project includes `Platforms/MacCatalyst/Keychain.entitlements.plist` when `CodesignProvision` is supplied; its Keychain
  access group uses the provisioning profile's App ID prefix and this app's bundle identifier. Use the same team
  and bundle identifier on subsequent builds to retain access. API keys are never saved to plain-text preferences.
  To reuse signing settings for ordinary local builds, create the gitignored `MacCatalyst.Signing.props` beside
  `Maui.Demo.Lite.csproj`:

  ```xml
  <Project>
    <PropertyGroup>
      <CodesignKey>Apple Development: Your Name (CERTIFICATE_ID)</CodesignKey>
      <CodesignProvision>PROFILE_UUID</CodesignProvision>
    </PropertyGroup>
  </Project>
  ```

  Keep this local file up to date when the development certificate or provisioning profile expires.
- The "+" button attaches images (from the photo library, the camera - "Take Photo", on devices with one - or the
  samples) or audio, and the microphone button records a voice message, for models that accept them; the first photo
  or recording asks for camera / microphone access.
- Settings → Context window (Gemma 4) sets how much of a chat the model keeps in mind: Automatic (8k tokens on a
  Mac or PC, 4k on a phone), 4k, 8k, 16k or 32k. A larger window summarizes the chat less often, but reading it again
  (opening a saved chat, after summarizing) takes longer and needs more memory. Changing it reloads the model; the chat
  continues.
- Settings → Search my photos (Gemma 4; off by default) indexes your most recent photos on the device in the
  background - nothing leaves it - with when, where and how they were taken, so you can ask "show me my photos of the
  beach", "selfies from Spain last summer" or "photos taken with my Pixel in 2025"; the matches appear as thumbnails
  above the reply. Places come from GPS positions and a list of towns in the app, `Resources/Raw/places.tsv.gz`
  (from [GeoNames](https://www.geonames.org), CC BY 4.0; rebuilt by `tools/make_places.py`). On Android the app also
  asks to read the photos' locations; without it, search works without places. Turning it off deletes the index.
- Settings → Embedding model selects Text Vision 440M (388 MB, default) or Multimodal 740M
  (485 MB). The choice is remembered and models download on first use. Switching releases the previous model,
  rebuilds an attached document's vectors, and reindexes photos. Only multimodal models are offered; a previous
  Text 270M selection uses Text Vision 440M instead. Windows builds with the matched WebGPU runtime also offer
  GPU entries for both models (text and vision, plus audio for 740M). Other platforms retain CPU entries.
  Switching backend reloads the embedder while retaining vectors for the same model; GPU loading failures offer
  CPU fallback. The demo's search tools currently use only text and images.
- Settings → Image-generation model lists Z-Image-Turbo · CPU, currently the only image model. Image generation
  remains unavailable on iOS; GPU execution is not offered because the complete Windows GPU pipeline failed testing.
- Settings → Image generation (Gemma 4; off by default; not on iOS) lets Gemma 4 draw pictures - "draw a red fox in
  the snow, watercolor" - with [Z-Image-Turbo](https://huggingface.co/Tongyi-MAI/Z-Image-Turbo) on the device: 256 x 256,
  shown above the reply and saved with the chat. Tap a generated picture to enlarge it, then **Save image…** to
  export the original PNG through the platform's save dialog. This also works for pictures reopened from saved chats.
  Turning it on downloads the 10.6 GB model (`Emgu.LiteRT.Models`'
  `ZImageTurbo`), and the first picture prepares about 9 GB of caches, so it needs about 21 GB of free space; "Delete
  the image model" removes it all. A picture takes about 25-40 s on an Apple M1, longer on a phone.
- "+" → Document attaches a PDF, Word (.docx) or text file to the chat, with any model. The selected embedding
  model is downloaded on first use; the document is then indexed on the device (a few seconds on a Mac,
  longer on a phone), and each question is sent with the parts of the document that match it - and, for Gemma 4 and
  Qwen3.5 0.8B, a matching picture or an image of a scanned page. A grey line above the reply says which pages were
  used. New chat removes the document.

## Troubleshooting

- **NU1201 / missing target frameworks:** re-run the project settings step (3).
- **Changes to `Platforms/*/Info.plist` don't show up (Mac Catalyst / iOS):** delete
  `bin/Debug/net10.0-<platform>` and `obj/Debug/net10.0-<platform>` and rebuild; incremental builds can keep a stale
  bundled `Info.plist`.
- **"isn't responding" / the app freezes:** Debug builds log every UI thread stall longer than a second
  (`UiStallWatchdog.cs`), with what the app was doing and, on Android, the main thread's stack: in the log (tag
  `UISTALL`; `adb logcat -s UISTALL`) and in `ui_stalls.log` in the app's data folder - on Android
  `adb shell run-as com.emgu.litert cat files/ui_stalls.log`.
- **The chat page's model fails to load:** check that the LiteRT-LM libraries were built for the platform (step 2)
  and that `git -C LiteRT-LM lfs pull` fetched real libraries, not Git LFS pointer files.
